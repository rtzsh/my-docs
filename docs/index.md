# 我的技术文档

欢迎访问我的个人文档网站。本网站使用 MkDocs 构建，通过 GitHub Actions 自动部署到 GitHub Pages。

- 作者：rtzsh
- 实践主题：静态文档自动部署
- 课程：开源软件开发实践 · 实践项目 2

## 这个网站是做什么的

这是一个用 Markdown 写成的四页文档站。我只需要编辑 `docs/` 目录下的 `.md` 文件并推送到 `main` 分支，
GitHub Actions 就会自动完成"安装依赖 → 构建 → 部署"，几十秒后公开网站的内容随之更新。
整个过程不需要我手动执行 `mkdocs gh-deploy`，也不需要登录服务器上传文件。

!!! note "为什么要做这个练习"

    文档写作本身不难，难的是"写完还要发布"这一步。把发布流程固化成工作流之后，
    写作和发布就被解耦了：我关心的只有正文，发布由机器保证一致性。

## 我的体会

这次实践我最大的改观是"发布"这一步可以彻底交给机器。以前交文档作业，改完要手动导出、
手动上传，改一个小错就得从头再来一遍；现在只需要 commit + push，剩下的安装依赖、构建、
部署全由 Actions 完成，第一次跑通时从 push 到网站更新只用了 39 秒。

中间也踩了坑：第一次 push 时正好赶上 GitHub 服务异常，Actions 里一条运行记录都没有，
我一度怀疑是 `paths` 过滤写错了。核对过工作流文件确实在默认分支上、改动的路径也确实匹配之后，
才确认是平台把事件丢了，重新推送一次就恢复正常。这件事让我意识到"配置正确"和"链路通畅"
是两件事，排查时得先分清是自己写错了，还是外部服务的问题。

## 快速开始

```bash
git clone https://github.com/rtzsh/my-docs.git
cd my-docs
python -m pip install -r requirements.txt
python -m mkdocs serve
```

自动部署验证：这是我第二次推送后更新的内容。
